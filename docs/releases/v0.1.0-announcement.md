**Title (Show HN):** Show HN: Lajstrom – apt, pypi, maven and raw repositories on top of your OCI registry

---

Most teams already run an OCI registry: ECR, Harbor, GHCR, Zot, plain distribution. Next to it
they often run a second system for packages (Nexus, Artifactory, a bucket with a script), with
its own storage, backups and permissions.

Lajstrom is one Go binary that serves apt, pypi, maven and raw-file repositories, and stores every
package as an OCI artifact in the registry you already have. It owns no bytes. Its only state of
its own is an index (SQLite or Postgres) and the users and permissions, and the index can be
rebuilt from the registry at any time.

What v0.1.0 does:

- `twine upload` and `pip install`; `mvn deploy` and Gradle; `.deb` uploads and `apt-get install`
  from a signed repo; `curl -T` for anything else. All of it uses the clients' own protocols,
  with no plugins.
- `/v2` in front of the registry with Lajstrom's own users and roles, so `oras`, `docker` and
  `cosign` work with the same tokens. Signatures and SBOMs are stored as referrers.
- Local users, personal access tokens and deploy tokens for CI, roles on repo masks, an audit log.
- Signed binaries and images with SBOMs, a Homebrew cask, Compose and Kubernetes examples.

Tested against distribution and Zot on every change, and by hand against GitLab's registry, GHCR
and Harbor. Not yet: npm, rpm, proxy repositories, OIDC, a UI. The list is in the release notes.

It is Apache-2.0. Before 1.0 the API may still change, but releases come on a schedule and the
license stays (the README has the promise).
